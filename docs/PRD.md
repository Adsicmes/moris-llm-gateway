## 2. 产品定位与目标

### 2.1 定位（已确认）

开发独立项目，在自有服务器上集中管理不同来源的模型接入、模型资料、供应商余额与订阅额度，并供本人多台设备使用。Metapi、LiteLLM、New API 等只作为调研参考，不以维护其分支作为本项目的开发基础。

“聚合模型”指把各供应商模型放入统一列表，保留供应商与渠道身份，不默认合并同名模型，也不自动跨供应商选路。

### 2.2 核心目标（已确认）

- 统一入口接入多个供应商，减少客户端重复配置。
- 通过独立插件包覆盖供应商的认证、模型发现、参数来源、分组与计价差异。
- 自动同步完整模型定义，首期支持 OpenCode v2 / OpenChamber v2，客户端只注册一个本网关 provider。
- 提供 OpenChamber 信息展示插件，在 Work Status 摘要区查看供应商余额与订阅额度。
- 监控真实供应商余额与订阅用量窗口，并明确区分网关内与网关外口径。
- 分别记录官方价、API 等价消费、供应商真实扣费与人民币实付，支持 USD / CNY 统计。
- 按上游真实窗口估算订阅的美元等价总额度与剩余额度，并标注估算依据与覆盖状态。

### 2.3 首期边界（已确认）

- 仅本人多设备使用（当前 3 台），不建设多人租户平台。
- 用量统计只覆盖经过本网关的请求，不导入或追踪网关外请求。
- 订阅估算按上游实际窗口分别计算，不预测整月可用额度。
- 只管理本网关 provider 的连接配置与模型定义，不接管其他 provider、Agent 或项目配置。
- 提供网页后台；手动实付账单统一以人民币（CNY）记录，不做自动成本分摊。
- 默认不跨供应商或分组回退；跨范围回退只能按用户手动配置的有序列表执行。

## 3. 部署与技术形态

### 3.1 运行形态（已确认）

- 服务端：Linux x64，8 核 CPU、16 GB 内存。
- 已有域名和 Caddy，Caddy 继续作为 HTTPS 入口与反向代理；不新增第二套入口。
- 采用 Docker Compose 部署，网关为单实例服务。
- 数据存储使用 SQLite 单实例，持久化到挂载卷；不引入 PostgreSQL、Redis 或多实例共享存储。
- 技术栈为 TypeScript + Node.js + Fastify + SQLite。Node、Fastify、SQLite 驱动等具体版本在实施时按兼容性核查后锁定，不在本文写死。
- 上游凭据加密后入库。加密主密钥独立于数据库注入（环境变量或独立挂载的密钥文件），不入库、不进镜像、不写入普通配置备份，并单独备份。
- 客户端到网关以及网关到上游都只依赖 HTTP / SSE；不在客户端启用 WebSocket 传输。

### 3.2 网络与代理（已确认边界）

服务器不能直连 OpenAI。代理可使用 HTTP / SOCKS5 代理或 Clash。代理覆盖范围必须包括授权、令牌刷新、模型发现、额度查询和推理链路，不能只覆盖推理请求。代理连通性与具体实现（含依赖选型）属待实测项。

### 3.3 单实例约束（已确认）

单实例意味着：统计、重试预算、同步任务与缓存都在同一进程内完成，不依赖跨实例协调；SQLite 使用 WAL 并只允许本进程写入。任何需要多实例的设计都超出首期范围。

## 4. 供应商接入与插件

### 4.1 首期接入对象

| 对象 | 已确认范围 | 待实测或待补充 |
| --- | --- | --- |
| realseek | 首期优先实现；`https://newapi.example.com`；具备账号访问令牌与用户 ID 的获取条件 | 实际分组、令牌权限、消费记录及分组动态变化 |
| 第二个 New API 实例 | 首期规模包含两个 New API 实例 | 实例名称、地址、版本在接入阶段提供；先以 realseek 建立适配能力 |
| vm2api | 自定义供应商插件验证对象，用于检验插件自由度 | 用户实例地址、版本、身份权限及可用接口 |
| OpenAI 订阅 | 一个账号，OAuth 登录；用户自述当前为每月 100 USD 的 Pro 套餐 | 目标账号授权、可用模型、窗口及套餐价格来源 |
| DeepSeek 官方 | 首期包含 API 接入及余额查询 | 目标账号连通性和余额接口实际返回 |

100 USD 是用户说明的当前套餐标价，不写死为全部 Pro 账号的价格；正式套餐信息由插件按可核实来源提供。

### 4.2 插件包与加载生命周期（已确认）

- 每个供应商适配为独立插件包，核心不内置具体供应商逻辑。
- 插件包按固定版本安装，不随核心升级自动变更版本；升级必须显式指定目标版本。
- 安装或升级后重启网关进程加载，首期不要求运行时热替换插件代码。
- 只安装可信来源的插件包；来源校验与完整性校验的具体机制属实施细节，但不得在运行时从任意地址拉取并执行代码。
- 插件加载失败不得影响核心启动其他已安装插件；失败原因必须可见，且对应供应商目录标记为不可用，而不是返回空目录冒充成功。

### 4.3 核心与插件边界（已确认）

核心负责：统一目录、数据持久化、任务调度、网关请求入口、重试与回退执行、统计账本、认证、客户端同步接口及网页后台。

插件负责：供应商事实与协议适配，包括凭据与认证方式、可用模型与参数、分组发现、价格与套餐资料、余额与额度查询、渠道原始计量单位解释、上游协议与必要参数差异。

核心不得硬编码 realseek 的分组名或 vm2api 的面板结构。插件契约必须能表达：数据来源、更新时间、能力支持状态、失败原因、原始单位，以及“不支持 / 未知 / 真实为零”的区别。

### 4.4 插件必须承载的能力（已确认）

- 凭据与认证：API Key、账号访问令牌、订阅 OAuth，以及刷新与失效处理。
- 模型发现：账号实际可用模型、模型参数、变体与限制。
- 路径定义：供应商标识之后的完整模型路径由插件负责。
- 分组：发现、命名、与请求凭据的绑定关系，以及变化处理。
- 计价：价格、套餐标价、余额、额度、消费记录中可取得的部分，以及原始单位换算。
- 协议：上游请求协议选择与参数适配。

某项能力不支持时，必须显式返回“不支持”或“未知”，不得以零值或空列表替代。

### 4.5 New API 动态分组与上游令牌（已确认）

`group-n` 一类路径段表示 New API 的令牌分组。分组发现、命名与凭据选择由对应插件负责，并按目录同步周期更新。

公开价格目录不等于账号实际可用目录，必须结合账号分组、令牌与模型权限判断。

上游令牌自动创建纳入首期，**默认关闭**。只有用户显式开启后，插件才可按配置创建令牌；普通定时目录同步不得隐式开启该功能。已确认规则：

- 令牌命名、额度与有效期使用供应商级模板配置。
- 优先复用本网关管理的既有令牌，避免重复创建。
- 不修改、不删除用户原有的其他令牌。
- 模板不完整时等待配置完成，不创建“猜出来”的令牌。
- 创建权限与接口兼容性仍需在目标实例实测。

### 4.6 配置与凭据边界（已确认）

上游凭据只留在服务器端，客户端同步目录不得带出上游密钥或 OAuth 刷新令牌。下游设备密钥与上游凭据分开管理。日志与错误信息不得输出敏感凭据。

## 5. 模型目录与命名

### 5.1 业务模型 ID（已确认）

格式：`供应商标识/插件定义的完整模型路径`。

示例（仅示意命名结构，不构成可用模型声明）：

```text
openai/gpt-6.1-sol
deepseek/deepseek-flash
realseek/group-n/gpt-6.1-terra
```

第一个 `/` 后的全部内容由对应插件控制，允许包含多级路径。

### 5.2 OpenCode 引用（已确认）

本网关 provider ID 固定为 `moris`，完整引用为：

```text
moris/openai/gpt-6.1-sol
moris/deepseek/deepseek-flash
moris/realseek/group-n/gpt-6.1-terra
```

网关负责解析业务模型路径；插件负责映射到上游实际模型标识。客户端展示标识、请求标识与上游标识之间的映射必须可追溯。OpenCode 发送请求时会剥离 provider 前缀，因此网关收到的 `model` 是业务模型 ID（如 `openai/gpt-6.1-sol`），`moris/` 只出现在 OpenCode 的引用与展示中。

### 5.3 最低模型定义（已确认）

| 信息 | OpenCode v2 对应字段 | 要求 |
| --- | --- | --- |
| 请求模型标识 | `modelID` | 与本网关路由映射一致 |
| 显示名称 | `name` | 可读、可区分供应商及渠道 |
| 模型家族 | `family` | 采用可核实资料 |
| 工具能力 | `capabilities.tools` | 明确是否支持工具调用 |
| 输入媒体 | `capabilities.input` | 首期至少文本、图片，按真实能力声明 |
| 输出媒体 | `capabilities.output` | 首期至少文本，按真实能力声明 |
| 上下文限制 | `limit.context` | 使用供应商实际限制 |
| 最大输出 | `limit.output` | 不与总上下文限制混淆 |
| 价格 | `cost` | 订阅模型为 0；其他按 9.3 的客户端口径 |
| 模型变体 | `variants` | 同步变体及对应请求参数，不能只同步名称 |

有独立输入限制、缓存、推理控制或协议兼容性信息时，在目标客户端支持的字段中一并表达。最终序列化格式按目标 OpenCode v2 版本校验。

### 5.4 参数来源与缺失处理（已确认）

- 优先使用已核实的供应商模型资料与实际限制。
- 缺失时精确匹配官方资料或 models.dev，并保留来源。
- 关键参数仍无法确定时，保留待补全条目，不启用为可选模型。
- 不以客户端对未知模型的默认限制冒充探测结果。
- 供应商限制比官方规格更严格时，不以官方规格覆盖供应商限制。
- 保存字段级来源与更新时间，便于排查目录差异。

### 5.5 目录同步语义（已确认）

- 每次同步生成完整目录快照；只有完整成功才确认新版本，部分成功不覆盖完整快照。
- 分组被删除后，停用对应旧模型路径，但保留历史记录与历史请求归属；不删除历史账目。
- 分组删除不主动终止在途请求；旧会话在下一次需要选择模型或发送提示时重新选择可用分组。
- 无明显证据的“改名”按“删除 + 新增”处理，不自动推断同一实体。
- 目录条目变更不得静默改写既有交易事实或历史价格快照。
- 同步失败时保留最后一次成功目录，并标记数据时间与状态。
- 缓存有效期为最后一次成功同步起 24 小时；后续读取不延长 TTL。
- 缓存超过 24 小时未成功刷新时，暂停受影响模型的新请求（返回明确错误），恢复成功同步后自动恢复；在途请求不因缓存过期被中断。
- 过期数据不得触发上游令牌的自动创建或删除。
- 手动配置的回退规则在目录改名无法证实的情况下仍可执行。

### 5.6 刷新周期（已确认默认值，可配置）

| 数据 | 默认周期 |
| --- | --- |
| 服务端模型目录、分组、价格 | 15 分钟 |
| 供应商余额与订阅窗口 | 2 分钟 |
| 客户端目录缓存 | 5 分钟 |
| Work Status 可见时读取网关缓存 | 60 秒 |
| 余额标记过期阈值 | 6 分钟未更新 |

余额超过 6 分钟未更新只标记过期，不因此停止模型调用。手动刷新必须合并重复查询；遇到上游限流时退避，不放大请求。

## 6. 客户端同步与展示

### 6.1 OpenCode 同步与重试插件（已确认）

首期提供 OpenCode v2 插件，负责：

- 从网关拉取本网关 provider 的目录与模型定义，写入 OpenCode 动态目录，不反复改写用户主配置文件。
- 保存本地缓存，启动或短时失败时按缓存恢复，并能标识数据时间与状态。
- 只管理 `moris` 这一个 provider 的连接与模型。
- 在本 provider 作用域关闭 OpenCode 客户端自动重试，把重试统一交给网关执行（见 7.3），避免双层重试叠加。

### 6.2 OpenChamber 信息展示插件（已确认）

提供独立 OpenChamber v2 插件，在 **Work Status 摘要区**展示：

- 供应商余额及原始币种／单位。
- 订阅各实际窗口的已用百分比与重置时间。
- 窗口美元等价总额度与剩余额度估算，明确标注为估算。
- 数据更新时间，以及未知／过期／获取失败状态。

展示范围严格限定为上述内容：不展示本网关用量摘要、人民币实付摘要、当前模型信息、独立连接与同步模块或网页后台入口。

数据来自本网关缓存，沿用服务端统计口径。订阅客户端 `cost = 0` 不得导致插件把 API 等价消费或实际付款误显示为 0。

### 6.3 发行与配置（已确认）

OpenCode 同步与重试插件、OpenChamber 展示插件分别发行、可分别独立安装，互不依赖。两者使用同一网关地址与对应设备的网关密钥；该密钥可用于模型调用、目录同步和余额／额度／估算查询，但不授予后台管理权限。

仅使用 OpenCode 的客户端仍可独立完成模型同步。

### 6.4 客户端价格表达（已确认）

- 订阅模型同步到 OpenCode 的 `cost` 为 0，表示不按 API 参考价产生客户端消费统计，不表示没有人民币实付成本。该判断取决于用户与直接供应商的付费关系，由插件声明，不因上游是中转或订阅形态而推断。
- 非订阅、按量计费的中转模型不得置为 0，也不得假免费。
- 客户端不表达复杂计价（阶梯、缓存读写差异、分组倍率、表达式等）。无法忠实表达时采用目标 OpenCode v2 契约允许的“未表达”形式，并在网关保留完整规则与结算结果；具体字段编码待实测锁定。
- 官方价、API 等价消费、供应商真实扣费与人民币实付在网关内部分开保存，不互相替代。

## 7. 请求路由、重试与失败处理

### 7.1 路由与协议（已确认）

- 用户通过业务模型路径明确选择供应商及插件定义的渠道。
- 不自动合并同名模型，不因同名自动增加回退目标。
- 路由必须尊重所选模型的上下文、工具与媒体能力。
- 同一 provider 内，每个模型可选择上游协议：Responses、ChatCompletions 或 Messages。
- 首期支持：文本与图片输入、文本输出、工具调用、流式输出、推理内容与模型变体。
- 其他媒体（音频、视频、文件等）后续扩展，未支持的能力在目录中明确声明。
- 客户端到网关只使用 HTTP / SSE，不启用客户端 WebSocket；供应商侧如有特殊传输，由插件适配并计入尝试次数。

### 7.2 重试执行权（已确认）

- 本网关 provider 关闭 OpenCode 客户端自动重试。
- 网关统一执行重试；客户端到网关的连接失败直接向用户报错，不由网关“替客户端重连”。
- 每次逻辑模型生成最多 3 次上游尝试（含首次、同目标重试与回退），该上限可配置。
- 工具续接产生的下一次生成、标题生成、上下文压缩、临时 `generate` 等各自拥有独立预算，不共享同一个 3 次额度。
- 用户手动重试或重发视为新的请求、新的预算；旧请求已产生的尝试与费用保留。
- 不同设备的任务分别计数。

### 7.3 可重试条件（已确认）

可重试：连接失败、超时、HTTP 429、502、503、504。

不盲目重试：认证失败、参数错误、上下文超限、请求本身不合法，以及任何需要用户修正输入才能成功的情况。此类失败直接返回明确错误，不切换模型掩盖问题。

重试使用有限退避，遵守上游 `Retry-After`，并受整次生成总期限约束。

### 7.4 跨范围回退（已确认）

- 默认不跨供应商或分组回退。
- 只有用户手动配置的有序回退列表才可跨范围回退；按列表顺序尝试，不自动扩展目标。
- 回退目标必须与所选模型在协议、上下文、工具与媒体能力上兼容。
- 统计必须保留实际命中的供应商／分组，不能把回退结果记到首选目标名下。
- 未配置回退时，保持原目标并返回对应失败信息。

### 7.5 输出锁定、取消与断线（已确认）

- 文字、推理内容或工具调用中任一有效输出送达客户端后，不再自动重放该次生成，也不自动切换到其他目标。
- 用户取消后停止后续尝试，并尽力取消上游请求；已产生的费用如实保留，不因取消而假定免费。
- 客户端到网关断线时直接报错；网关不把客户端断线当作可重试的上游错误。

### 7.6 超时（已确认默认值，可配置）

| 项目 | 默认值 |
| --- | --- |
| 建立上游连接 | 15 秒 |
| 上游首个响应事件 | 120 秒 |
| 流式无事件间隔 | 90 秒 |
| 整次生成（含全部重试与回退） | 15 分钟 |

心跳或保活事件不取消整次生成的总期限。任一超时都必须落到明确的错误与账目记录，不能静默挂起。

### 7.7 统计层级（已确认）

每次逻辑模型生成与每次上游 attempt 分别记录：

- 生成级：请求身份、所选模型、预算、最终结果、是否回退、客户端可见输出状态。
- 尝试级：目标供应商／分组、协议、开始与结束、错误分类、是否产生用量、估算费用、真实扣费对账状态。

失败、取消、超时的 attempt 都可能产生费用，必须保留记录；无法确认是否收费时标记“未知”，不能记为 0。

## 8. 认证与权限

### 8.1 网页后台（已确认）

- 单管理员账号，使用密码登录。
- 经现有 Caddy 以 HTTPS 提供，使用浏览器登录会话。
- 不建设多用户、角色或租户体系。
- 登录会话时长、失败次数限制与限流阈值属实施默认值，在实施文档中确定。

### 8.2 设备密钥（已确认）

- 每台设备使用独立命名、可单独撤销的网关密钥。
- 设备密钥可用于模型调用、目录同步、余额／额度／估算查询，以及 Work Status 展示读取。
- 设备密钥不授予任何后台管理权限。
- 不单独设立只读额度凭据；额度查询由设备密钥承担。
- 撤销后该设备立即无法调用与查询；已产生的历史账目保留。

### 8.3 管理权限边界（已确认）

只有管理员密码会话可以修改供应商、凭据、目录配置、回退规则、汇率、设备密钥、自动创建令牌开关、账单与后台设置。设备密钥只能读取自身可用的目录与统计信息并发起模型调用。

## 9. 计价、账本与真实账单

### 9.1 统计边界（已确认）

只统计经过本网关的请求。供应商余额与额度可能反映整个账号，包含网关外使用；必须说明该区别，不能把账户余额差额直接归因于本网关请求。

### 9.2 四类金额分开保存（已确认）

| 口径 | 含义 | 不得混淆的内容 |
| --- | --- | --- |
| 官方价 / 套餐标价 | 插件提供的官方 API 价或订阅标价 | 标价不等于实际人民币付款 |
| API 等价消费 | 按适用参考价计算的请求价值 | 订阅场景下不是新增现金支出 |
| 供应商真实扣费 | 与 attempt 关联的上游结算金额或原始额度扣减 | 余额变化不一定全来自本网关 |
| 人民币实付 | 用户手动记录的充值、续费金额（CNY） | 实付与后续扣费不能相加当作成本 |

另保留：原始用量与限额（Token、渠道额度单位、窗口百分比、重置时间），以及窗口额度估算（由等价消费与已用比例推算，不得称为官方承诺额度）。

### 9.3 `cost = 0` 的判定（已确认）

- 只有用户与**直接供应商**之间存在订阅付费关系时，该供应商的订阅模型才可声明 `cost = 0`。
- 该付费关系由对应插件声明，不由核心猜测。
- 中转或按量计费的供应商即使上游自身使用订阅，也不能声明为 0；其模型必须按适用规则计价或标记为未表达，不能假免费。
- 复杂计价在客户端不表达，但网关必须保留规则与真实结果。

### 9.4 价格来源与快照（已确认）

- OpenAI API 等价价格由插件依据官方价格获取。
- New API 模型价格依据具体站点、令牌分组与适用计价条件获取。
- 套餐标价由订阅插件提供。
- 其他供应商由各自插件解释原始计价单位与规则。
- 价格可能包含分组倍率、缓存读写、长上下文阶梯或表达式规则，不能一律简化为 Token 乘单价。
- 每次请求保存使用的价格版本与计算依据快照，避免新价覆盖旧账。

### 9.5 估算与对账（已确认）

- 真实扣费存在延迟：先按可用 Token 与适用价格估算，之后用上游真实记录对账。
- 只有存在 Token 与适用价格时才估算；数据不足记为“未知”。
- 真实扣费与估算值不相加、不重复计入总额；对账后以真实值替换该 attempt 的结算口径，同时保留估算依据。
- 余额变化不能直接当作请求扣费；无法关联到 attempt 的账户变动不摊入请求。
- 失败、取消、超时的 attempt 同样参与估算与对账，可能收费，不得默认免费。

### 9.6 手动人民币账单（已确认）

- 仅简单增删改，删除前必须确认。
- 退款以负数金额加备注记录，计入净实付。
- 必填：供应商、付款日期、金额。
- 可选：账期、付款方式、备注。
- 保留创建时间与修改时间。
- 不建审批流，不做完整版本历史，不做礼品卡成本跨账期分摊，不把订阅实付分摊到单条请求。

### 9.7 汇率（已确认）

- 汇率方向为 1 USD 对应多少 CNY，可手动配置；自动汇率服务后期接入。
- 新汇率只对新请求的折算生效；历史请求保留当时汇率快照。
- 没有配置汇率时只显示原币，不猜测换算。
- 当前余额可按最新汇率提供参考折算，实付人民币金额永不因汇率更新而重算。
- 站点显示 USD 或提供 `quota_per_unit` 不能证明用户的人民币采购成本或充值折扣。

### 9.8 统计时区（已确认）

统计与日期归属使用 Asia/Shanghai；底层时间戳按 UTC 存储。订阅窗口使用上游真实起止时间，不按自然月强行切分。

## 10. 订阅美元额度估算

### 10.1 目标（已确认）

按上游真实用量窗口分别估算总额度与剩余额度。上游提供 5h 与周窗口时独立计算二者；窗口名称与长度以实际数据为准，不对全部账号写死。不叠加重叠窗口，不用套餐价格代替用量上限，不预测整月容量。

### 10.2 计算口径（已确认）

在相同账号、相同额度池、相同窗口、相同采样截止时刻下：

```text
S = 窗口内经本网关请求的 API 等价消费（USD）
p = 上游窗口已用比例，归一化到 0～1
估计总额度 T = S / p
估计剩余额度 R = max(T - S, 0)
```

例：本网关在周窗口内记录等价消费 40 USD，上游显示已使用 20%，则估计总额为 200 USD、剩余为 160 USD。该数值不是套餐标价，也不是现金余额。

### 10.3 有效窗口条件（已确认）

必须同时满足：

- 使用当前完整窗口，且本网关记录覆盖窗口起点。
- 已用比例不低于 5%（可配置）。
- 窗口内消费大于 0。
- 窗口未过期。
- 窗口内不存在未知用量或未定价 attempt。
- 本网关消费与上游比例使用同一采样截止时刻。

任一条件不足时显示具体原因，不使用历史窗口替代，不做平滑或外推。

### 10.4 网关外使用（已确认）

上游比例可能包含网关外消费，而 S 只包含本网关记录，因此混合使用会使估算偏低。输出必须标注“基于本网关记录的估算”，同时显示窗口、采样时间、覆盖状态与价格依据。不得承诺这是官方额度、精确余额或严格下界。

## 11. 管理后台

### 11.1 页面范围（已确认）

首期网页后台覆盖：

- 供应商、账号授权与网络代理配置。
- 模型目录、分组、参数来源与同步状态。
- 余额、订阅窗口百分比、重置时间及额度估算。
- 本网关请求用量、供应商扣费与 API 等价消费（按生成与 attempt 可追溯）。
- 人民币实付账单录入与按账期查看。
- 插件配置、自动创建令牌开关（默认关闭）与刷新状态。
- 手动回退规则与汇率配置。
- 设备密钥管理与撤销。

页面布局与视觉方案在实施阶段确定，不改变上述功能范围。

### 11.2 展示口径（已确认）

- 未知、获取失败、过期与真实零余额必须可区分。
- 估算值必须与真实扣费、实付、官方价在视觉与文案上分开。
- 统计日期按 Asia/Shanghai 展示，底层仍为 UTC。

## 12. 数据、日志与备份

### 12.1 数据保存（已确认）

- 不持久保存提示词、回复正文、图片与工具调用参数。
- 保存结构化的请求／attempt 元数据、Token、费用、价格依据、对账状态与账单。
- 临时转发数据不进入历史存档。
- 结构化账目不自动清理。
- 脱敏运行日志保留 14 天。
- 日志和错误信息不得包含上游密钥、OAuth 刷新令牌或设备密钥明文。

### 12.2 备份（已确认）

- 每日执行一致性本地备份，保留 7 天，另有 4 周度备份。
- 备份必须使用 SQLite 一致性备份机制，不能在写入过程中直接复制数据库文件。
- 加密主密钥单独备份，不与普通数据库备份打包在同一份文件中。
- 恢复流程必须可用同一主密钥解密既有上游凭据；主密钥丢失视为上游凭据不可恢复。

以下为标准草案，用于实施验收，不代表当前已验证。涉及外部实例与 SDK 的条目只有实测通过才算完成。

| 编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 同名模型来自不同供应商或分组 | 目录身份不混淆，请求到达所选目标 |
| AC-02 | 三台客户端加载本网关 | 仅新增 `moris` 一个 provider，模型字段一致，其他配置保持原状 |

| AC-04 | 模型关键参数缺失 | 可追溯来源；完全未知模型暂不启用 |

| AC-06 | 上游余额／额度查询失败 | 显示失败或过期，不显示为真实零余额或额度耗尽 |
| AC-07 | 同一笔充值随后产生请求扣费 | 实付金额不与扣费重复相加 |
| AC-08 | 订阅采用不同付款方式续费 | 可按账期记录不同实付金额，独立保留套餐标价 |
| AC-09 | 订阅窗口数据完整且可定价 | 按窗口输出美元等价总额与剩余估算，标注来源、采样时间与覆盖限制 |
| AC-10 | 日志不足、未定价或窗口已重置 | 不输出貌似精确的当前窗口总额度，并显示原因 |
| AC-11 | 网关外产生消费 | 不导入为本网关统计；账户额度与本网关估算口径可区分 |
| AC-12 | 服务器通过代理连接 OpenAI | 授权、刷新、查询与推理链路均可工作 |
| AC-13 | 重启客户端或同步短时失败 | 按缓存恢复目录，并可识别数据时间与状态 |
| AC-14 | 未配置回退规则时目标失败 | 不跨供应商或分组回退；显式配置后仅按有序列表选择 |
| AC-15 | 发现需要新令牌的分组 | 默认不创建；开启后按供应商模板创建并优先复用本网关令牌，不动用户原有令牌 |
| AC-16 | 订阅模型同步到 OpenCode | `cost` 为 0，网关仍独立计算 API 等价消费 |
| AC-17 | 用户录入实际付款 | 账单金额为 CNY，无需填写成本分摊或外币付款账户 |
| AC-18 | 更新汇率配置 | 原始金额、历史快照与手动人民币账单不变，折算值明确标识 |
| AC-19 | OpenChamber 信息展示插件启用 | 在 Work Status 展示余额、窗口比例／重置时间与美元估算，未知／过期可区分 |
| AC-20 | 上游在首次尝试后返回 503 | 网关按预算重试，attempt 分别记录；总尝试不超过配置上限 |
| AC-21 | 已有文字或工具调用送达客户端后上游中断 | 不自动重放、不切换目标，向客户端报错并保留已发生费用 |
| AC-22 | 用户取消生成 | 停止后续尝试，尽力取消上游，已发生费用保留 |
| AC-23 | 客户端到网关连接中断 | 直接报错，不由网关隐式重连或重放 |
| AC-24 | 认证失败或上下文超限 | 不盲目重试或换模型，返回明确错误 |
| AC-25 | 目录同步连续失败超过 24 小时 | 受影响模型的新请求被拒绝并说明缓存过期；恢复同步后自动恢复；在途请求不中断 |
| AC-26 | 分组被删除 | 旧路径停用，历史与账目保留，在途请求不终止，旧会话下次提示时重选 |
| AC-27 | 无证据的分组改名 | 按删除加新增处理，不自动继承旧身份 |
| AC-28 | 一次生成包含 2 次重试和 1 次回退 | 生成级 1 条、attempt 级逐条记录，回退命中目标如实标注 |
| AC-29 | 上游真实扣费延迟到达 | 先显示估算，后按真实值对账，二者不相加，未知保持未知 |
| AC-30 | 订阅窗口比例低于 5% 或含未定价 attempt | 不输出估算总额，显示不满足条件的具体原因 |
| AC-31 | 无汇率配置 | 只显示原币，不生成猜测的 CNY 金额 |
| AC-32 | 撤销某台设备密钥 | 该设备调用与查询立即失败，其他设备不受影响 |
| AC-33 | 设备密钥访问后台接口 | 被拒绝，设备密钥不具备管理权限 |
| AC-34 | 管理员登录后台 | 仅密码登录；未登录会话无法修改任何配置 |
| AC-35 | 备份与恢复 | 使用一致性备份；主密钥单独保存；恢复后上游凭据可解密且历史账目完整 |
| AC-36 | 安装固定版本供应商插件并重启 | 插件按固定版本加载；加载失败不影响其他插件，且状态可见 |
